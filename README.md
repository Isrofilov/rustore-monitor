# RuStore Monitor Bot

Бот для мониторинга отзывов, оценок, платежей, модерации и доступов приложений в RuStore с уведомлениями в Telegram и/или Matrix.

## Возможности

- **Новые отзывы** — мгновенное уведомление о новых отзывах с текстом и оценкой
- **Редактирование отзывов** — каждая правка, с показом «было → стало» по оценке и тексту
- **Оценки без текста** — обнаружение «тихих» оценок по изменению распределения
- **Платежи** — уведомления о новых подтверждённых платежах (покупки и подписки)
- **Возвраты** — уведомления о возвратах средств и отменённых холдах
- **Подписки** — в уведомлении о платеже: первая оплата или продление, пробный период, дата окончания, отключённое автопродление
- **Модерация версий** — автопроверка, модерация, одобрение, отклонение, публикация, изменение доли частичной публикации
- **Доступы** — выдача, отзыв и смена ролей пользователей консоли
- **Сводки** — ежедневная и/или еженедельная: платежи и возвраты, отзывы, динамика рейтинга, опубликованные версии
- **Несколько приложений** — одним ботом и одним ключом API
- **Предупреждения о сбоях** — если проверка падает несколько раз подряд (например, у ключа нет доступа к методу)
- **Статистика** — текущий средний рейтинг и распределение оценок в каждом уведомлении об отзывах

## Быстрый старт

### Docker Compose (рекомендуется)

1. Клонируйте репозиторий:

```bash
git clone https://github.com/isrofilov/rustore-monitor.git
cd rustore-monitor
```

2. Скопируйте `.env.example` в `.env` и заполните переменные:

```bash
cp .env.example .env
```

3. Запустите:

```bash
docker compose up -d
```

Docker Compose автоматически подхватывает переменные из `.env` файла и прокидывает их в контейнер через секцию `environment` в `docker-compose.yml`.

### Docker (без Compose)

```bash
docker run -d \
  --name rustore-monitor \
  --restart unless-stopped \
  --env-file .env \
  -v rustore-monitor:/data \
  isrofilov/rustore-monitor:latest
```

### Запуск из исходников

```bash
git clone https://github.com/isrofilov/rustore-monitor.git
cd rustore-monitor
pip install -r requirements.txt
python -m rustore_monitor
```

## Переменные окружения

| Переменная | Обязательная | Описание |
|---|---|---|
| `RUSTORE_KEY_ID` | да | ID ключа API RuStore |
| `RUSTORE_PRIVATE_KEY` | да | Приватный RSA-ключ в формате base64 |
| `RUSTORE_PACKAGE_NAME` | да* | Имя пакета приложения (например, `com.example.app`) |
| `RUSTORE_APP_ID` | да* | Числовой ID приложения из консоли RuStore |
| `RUSTORE_APPS` | нет* | Несколько приложений: `пакет:appId[:название]` через запятую (см. [ниже](#несколько-приложений)) |
| `TELEGRAM_BOT_TOKEN` | для Telegram | Токен Telegram-бота (получить у [@BotFather](https://t.me/BotFather)) |
| `TELEGRAM_CHAT_ID` | для Telegram | ID чата для уведомлений |
| `TELEGRAM_THREAD_ID` | нет | ID темы в супергруппе |
| `TELEGRAM_DOMAIN` | нет | Домен Telegram API (по умолчанию `api.telegram.org`) |
| `MATRIX_HOMESERVER` | для Matrix | URL домашнего сервера Matrix (например, `https://matrix.org`) |
| `MATRIX_ACCESS_TOKEN` | для Matrix | Токен доступа Matrix-пользователя |
| `MATRIX_ROOM_ID` | для Matrix | ID комнаты для уведомлений (например, `!abcdef:matrix.org`) |
| `POLL_INTERVAL` | нет | Интервал опроса в секундах (по умолчанию `300`) |
| `TZ_OFFSET` | нет | Смещение часового пояса в часах (например, `3` для UTC+3). По умолчанию — `3` (МСК) |
| `PAYMENTS_LOOKBACK_DAYS` | нет | За сколько последних дней проверять платежи и возвраты (по умолчанию `7`) |
| `CHECK_VERSIONS` | нет | Уведомления о статусах версий: `1`/`0` (по умолчанию `1`) |
| `CHECK_ACCESS` | нет | Уведомления об изменении доступов: `1`/`0` (по умолчанию `1`) |
| `CHECK_SUBSCRIPTIONS` | нет | Данные подписки в уведомлении о платеже: `1`/`0` (по умолчанию `1`) |
| `DIGEST_DAILY` | нет | Ежедневная сводка за вчера: `1`/`0` (по умолчанию `0`) |
| `DIGEST_WEEKLY` | нет | Еженедельная сводка за прошедшие 7 дней: `1`/`0` (по умолчанию `0`) |
| `DIGEST_WEEKLY_DAY` | нет | День недели еженедельной сводки: `1` — понедельник … `7` — воскресенье (по умолчанию `1`) |
| `DIGEST_TIME` | нет | Время отправки сводок `ЧЧ:ММ` в часовом поясе `TZ_OFFSET` (по умолчанию `09:00`) |
| `ALERT_AFTER_FAILURES` | нет | После скольких подряд упавших проверок присылать предупреждение (по умолчанию `3`, `0` — выключить) |
| `DATA_DIR` | нет | Каталог для баз состояния (по умолчанию `/data`) |

\* Задайте либо `RUSTORE_PACKAGE_NAME` + `RUSTORE_APP_ID` (одно приложение), либо `RUSTORE_APPS`.

Настройте хотя бы один канал уведомлений — Telegram (`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`) и/или Matrix (`MATRIX_HOMESERVER` + `MATRIX_ACCESS_TOKEN` + `MATRIX_ROOM_ID`). Можно включить оба одновременно — уведомления уйдут в каждый. Если ни один не настроен, бот завершится с ошибкой при старте.

## Получение ключей RuStore API

1. Откройте [Консоль RuStore](https://console.rustore.ru/)
2. Перейдите в раздел **Приложения** → **API RuStore**
3. Создайте новый ключ, выбрав следующие методы:
   - Получение списка продуктов приложения
   - Получение списка подписок приложения
   - Получение рейтинга приложения
   - Получение отзывов приложения
   - Получение списка платежей за выбранную дату («Получение данных платежа»)
   - Получение данных подписки (v5) — для `CHECK_SUBSCRIPTIONS`
   - Получение статуса версий приложений — для `CHECK_VERSIONS`
   - Получение информации о выданных доступах по приложению — для `CHECK_ACCESS`
4. Скопируйте `KEY_ID` и приватный ключ
5. `APP_ID` это номер вашего приложения в RuStore. Он указан в адресе страницы приложения в консоли (например: в `.../apps/123456/...` нужное значение — `123456`).

Если какой-то метод не выбран при создании ключа — отключите соответствующую проверку (`CHECK_VERSIONS=0` и т. п.), иначе бот будет присылать предупреждение о сбое.

## Несколько приложений

Один бот может следить за несколькими приложениями аккаунта — ключ API общий. Перечислите их в `RUSTORE_APPS` через запятую в формате `пакет:appId[:название]`:

```env
RUSTORE_APPS=com.example.app:123456:Моё приложение,com.example.game:654321:Игра
```

Название необязательно (по умолчанию — имя пакета) и показывается заголовком в каждом уведомлении, когда приложений больше одного. Сводки приходят отдельно по каждому приложению.

## Сводки

```env
DIGEST_DAILY=1        # каждый день — за вчера
DIGEST_WEEKLY=1       # раз в неделю — за прошедшие 7 дней
DIGEST_WEEKLY_DAY=1   # в понедельник
DIGEST_TIME=09:00     # в 09:00 по TZ_OFFSET
```

В сводке: число и сумма платежей (по дате создания счёта) и возвратов среди них, отзывы за период по звёздам (из последних 100), изменение числа оценок и среднего рейтинга с прошлой такой же сводки, опубликованные сейчас версии. Если бот был выключен в момент `DIGEST_TIME`, сводка придёт при первом запуске в тот же день.

## Как получить `TELEGRAM_CHAT_ID`

Самый простой способ — добавить бота в целевой чат и написать туда любое сообщение, затем открыть:

```
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

В ответе найдите `"chat":{"id": ...}`. Для супергрупп ID начинается с `-100`.

Для `TELEGRAM_THREAD_ID` — отправьте сообщение в нужную тему и посмотрите `message_thread_id` в том же ответе.

## Как получить реквизиты Matrix

1. **`MATRIX_HOMESERVER`** — адрес домашнего сервера, на котором зарегистрирован бот (например, `https://matrix.org` или ваш self-hosted сервер).
2. **`MATRIX_ACCESS_TOKEN`** — токен доступа пользователя-бота. В Element: **Настройки** → **Справка и информация** → **Дополнительно** → **Access Token**. Либо через API:

   ```bash
   curl -XPOST 'https://matrix.org/_matrix/client/v3/login' \
     -d '{"type":"m.login.password","user":"BOT_USER","password":"PASSWORD"}'
   ```

   В ответе — поле `access_token`.
3. **`MATRIX_ROOM_ID`** — внутренний ID комнаты (начинается с `!`, не путать с алиасом `#room:server`). В Element: **Настройки комнаты** → **Дополнительно** → **Внутренний ID комнаты**. Бот-пользователь должен быть участником этой комнаты.

### Как вступить ботом в комнату

Бот не сможет отправлять сообщения, пока не станет участником комнаты. Варианты:

- **Через клиент** — пригласите бота в комнату (по его `@user:server`) из любого Matrix-клиента, затем примите приглашение от имени бота.
- **Через API** — вступите напрямую токеном бота. Подходит и room ID (`!...`), и алиас (`#room:server`):

  ```bash
  curl -XPOST 'https://matrix.org/_matrix/client/v3/join/!abcdef:matrix.org' \
    -H 'Authorization: Bearer MATRIX_ACCESS_TOKEN' \
    -H 'Content-Type: application/json' -d '{}'
  ```

  В ответе вернётся `{"room_id":"!abcdef:matrix.org"}` — значит бот в комнате. Если комната приватная, бота сначала нужно туда пригласить, иначе вступление вернёт ошибку `M_FORBIDDEN`.

  Если вступаете по **алиасу**, символ `#` нужно заменить на `%23` (это разделитель фрагмента в URL), остальное можно оставить как есть: `.../join/%23room:matrix.org`.

## Сертификаты Минцифры

Docker-образ доверяет корневому и промежуточному сертификатам НУЦ Минцифры («Russian Trusted Root CA» / «Russian Trusted Sub CA») — на случай, если API RuStore или ваш Matrix-сервер используют сертификат, выпущенный НУЦ. Сертификаты скачиваются с `gu-st.ru` при сборке образа: корневой сверяется по SHA-256 отпечатку, промежуточный — проверяется его подписью. Затем они добавляются в системное хранилище, и через `SSL_CERT_FILE` их подхватывает httpx (вместе со стандартными публичными CA).

При запуске из исходников установите сертификаты в систему ([инструкция Госуслуг](https://www.gosuslugi.ru/crt)) и укажите путь к системному хранилищу:

```bash
export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt
```

## Первый запуск

При первом запуске бот сохраняет текущее состояние (отзывы, оценки, платежи, версии, доступы) в БД и **не отправляет** уведомления за прошлый период — чтобы не засыпать чат историей. Уведомления начнут приходить со следующей итерации. То же происходит с каждой новой проверкой после обновления бота.

## Хранение состояния

Бот сохраняет состояние в SQLite-базах `/data/state-<пакет>.db` (по одной на приложение) внутри контейнера. При использовании Docker Compose данные хранятся в именованном томе `rustore-monitor` и сохраняются между перезапусками. База `/data/state.db` от предыдущих версий бота переносится автоматически.

После каждой итерации бот обновляет файл `/data/heartbeat` — по нему Docker `HEALTHCHECK` определяет, что бот не завис (`docker ps` покажет `healthy`/`unhealthy`).
